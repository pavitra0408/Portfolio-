- **Discipline pages for launch (2026-10-30).** UI/UX "worked through": each project as steps (problem, finding, design, system) beside one screen that changes with the step; copy from the case studies. Motion "edit timeline": a monitor above a timeline where each clip is as long as its film (read from metadata); muted preview with a pause control, playhead follows playback. Experiments "ignite": Kal Bhairav's calm and ignited renders under a pointer lens (the piece's own crossfade idea), keyboard toggle, silent preview that loads only on screen. - **Hidden for launch:** Indian Travel Learning Platform (`hide:1` on the project; `DHID` removes hidden projects from `D` after slugs are set, so no listing, count or route exposes it; a direct link shows the UI/UX page). Two placeholder lines in DigiLocker and Recurring are HTML comments now. Nothing deleted.
- **Photography index "Exposures" (2026-10-30, built, awaiting review).** One roll of film: a full-width opening frame (Soul s1), then four chapters, each one large frame (a full-bleed band or a tall portrait beside its header) followed by smaller detail frames at their real ratios; Portraits ends with the six-frame studio sitting as a contact strip. One motion: a shutter slit that opens (clip-path, in-out curve) while the image settles from 1.1x and brightens; crop marks on hover/focus (garnet on keyboard focus). Light parallax on large frames, fine pointer only. All copy from the series pages and alt text. Every frame opens the shared viewer, which now steps through all 23 index frames. Scoped to `.pw`/`photoIdx`/`pwInit`/`pwStop`.
- **Background (2026-10-29): A topography + B wireframe + C dark sculpted surface**, one persistent `#env` canvas built at boot (`envInit`), never rebuilt by `route()`. Height field of slow sines + cursor bump drives contour lines (marching squares), a displaced perspective lattice, and soft slope shading under a drifting light. Garnet is one contour lit by a slow band every 13s. Text blocks are measured and feathered out of the lines (quiet zones) on scroll/resize/route. Reduced motion = one still frame; touch/small/low-core = lighter (bigger cells, 20fps, no wireframe). The old field (`fieldStart`) is retired (returns early, canvases hidden); the radar rings (`#rg1`, `#rp1`) are kept.
- Case-study motion language: `[data-mv]` reveals via one IntersectionObserver gated on `body.ready`; kinds: wipe (wl/wu), zoom, rise, lights, slash (garnet bar, Chainsaw Man only), draw (construction), ok/no (usage ticks and slashes). ARCEON hero: mark builds (dot, ring, wordmark wipe) from the real logo paths.
- Colour: black foundation, slate secondary, garnet `#C03A4A` sparingly. Outfit + DM Mono only.
- Visual discipline page: C "Plates" (type index + one art-directed plate) with A "Aperture" (one ring that sits on real geometry). Approved 2026-10.
- Visual case studies lead with the finished work, then details. Detail crops are windows onto the real images; captions use sentences already on the page or plain description of what is visible. No process stages are invented.
- Project-detail pages use the fixed interference field (same mode as About/Contact), pushed to the right so it stays off the text column.
- Homepage radar previews sit beneath the rectangles by design and are kept clear of them (see Bugs).

## Rejected directions
- Animating elements that are clipped to nothing and observing them directly: IntersectionObserver never fires for a fully clipped element (caught in testing). Hidden states keep 0.5px visible.
- Concept B "Ember" (warm grain, glow) for Visual: off-identity, washed black to grey.
- Persistent RGB split on text, glitch effects, glows, particles: rejected; the colour split runs once (~0.75s) on selection change only.
- Redrawing logos or generating process images: rejected (real assets only).
- Contain-fitting the landscape ARCEON mockup in a 4:5 plate: left large black bars; a deliberate crop on the card is used, the full image is on the case study.

## Bugs and verified fixes
- **Black shadow behind the About portrait.** Cause: the asset itself. `port_dark.jpg` is the portrait composited onto solid black, so a black rectangle sat on the dark-grey background canvas, edges faded only by CSS masks. Fix: a real transparent cutout (alpha PNG); no shadow, glow or vignette added.
- **Visual index title overlap (2026-10-29).** Cause: `.vz` had `max-width:1920px` and `padding:0 var(--edge)`; `--edge` already centres the page against 100% width, so on viewports wider than 1920 the padding grew (556px a side at 2560) and the content box shrank to about 800px, the index column to about 300px, and the no-wrap 62px "Chainsaw Man" ran under the plate (reproduced at 2560: title right 1297 vs plate left 1272). Fix: removed the max-width; index column is a size container (`.vzt`), title size = (column width - 190px) / 6.7 clamped 32-62px, row grid `44px minmax(0,1fr) auto`, `text-wrap:balance`, no `nowrap`. Verified at 1100, 1280, 1366, 1440, 1920, 2560, 3440 for all three titles (always one line, inside the row, clear of the tag and the plate).
- **Background softness (2026-10-29).** Technology: one Canvas 2D (`#env`), no WebGL/SVG. Cause: backing store was a fixed 0.5x of CSS size, stretched by CSS, with line widths defined in canvas px. Fix: scale = min(devicePixelRatio, 2) under a pixel budget (4.2M px full, 1.6M lite); contour cell 12 CSS px; line widths and wire amplitudes in CSS px times scale; 64-point wire polylines; recomputed on resize and on devicePixelRatio change (`resolution` media query). Measured: 1440x900@1 1.0x (1.3MP), @2 1.8x (4.2MP), 2560x1440@1 1.0x (3.7MP), @2 1.07x (budget), 1920x1080@3 1.42x; frame cost 1.8-4.8ms.
- **Viewport-edge black strip (2026-10-29): capture-only, no code change.** In-page geometry over 601 scroll frames: `#env` stayed at 0,0 1440x900, `visualViewport` offset 0. In mid-scroll screenshots from two different capture paths the whole frame, including the fixed header, is shifted by the strip height; static captures after scrolling show no strip. Not observed on a real display.
- **Tall crops blank on phones (found 2026-10-29).** The `wu` hidden state kept its sliver at the bottom edge, so a tall crop only revealed once its bottom was inside the observer margin. Sliver now at the top; verified by jumping straight to every `[data-mv]` element at 1440 and 390 (0 late of 35 per run).
- **Collage overlap hid brand details.** The right column hid 12px of the laptop photo (the mug's "ARCEON") and the folder. Folder pair and laptop now stop short; only 12px of the bottle photo's plain wall is tucked under.
- **Scroll shadow (2026-10-29).** Cause: my background's "quiet zones" were dark feathered boxes painted over the whole canvas (base and shading included) and rebuilt on a 140ms scroll timer, so dark patches sat behind text and lagged behind it while scrolling. Fix: quiet zones now erase only the line layer (contours, wireframe, garnet) via an offscreen layer with destination-out, and the mask is rebuilt once per scroll frame. Verified: canvas luminance behind a paragraph equals luminance above it (18.08 vs 18.07), and mean canvas brightness stays 15.1-15.5 across 27 scroll positions. A mid-scroll dim on images is the existing opacity fade-in (`.rvf`), not an overlay.
- **Scroll shadow, second and verified cause (2026-10-29).** A mid-scroll screenshot showed white panels grey and see-through with contour lines visible through them. The site's older reveal classes (`.rvt`, `.rvi`, `.rvs`) fade whole blocks in from opacity 0; a block that is on screen but mid-fade is dim and translucent and lags fast scrolling. Fixed for Visual case studies with `.cs .rvt,.cs .rvi,.cs .rvs>*{opacity:1!important;transform:none!important;transition:none!important}`. The line-only quiet-zone change above is kept. Continuous scrolls down (30px/frame) and up (12px/frame) show solid panels. Other pages still use the fade.
- **Case studies felt narrow.** `.w` capped pages at 1440px. Visual case studies now use `.pg.w.cs` (max 1920px, gutter-matched), `body.cswide` aligns the header edge, image-led sections take 10 of 12 columns, text stays at 62ch.
- **Gap under the ARCEON hero.** The headline sat below a 21:9 plate and was hidden until it scrolled into view, leaving blank space after the logo reveal. Plate is now min(44svh, 420px) and the headline sits 28px under it, visible on the first screen. The scroll-built logo scene ends 95px above the next heading (section padding 64px on case studies). Its post-completion hold (about 6% of the scene) was left as designed.
- **Logo-in-use collage.** Three rows, 10px gutters, ragged column widths, one 6px radius, per-image `object-position`. The repeated symbol image (`arcUsage`, a favicon/app-icon sheet that repeats the mark section) was removed from the markup; `img/arcUsage.jpg` and its `IMG` entry stay on disk.
- **Radar reveal frequency (2026-10-29).** Sweep took 7.4s with a 5.2s gap and a 3.5s cooldown, so reveals came about every 18s. Now: sweep 5s, 0.7s gap, a queue of the two newest touched rectangles, one reveal per 2.4s (`RV.gap`), preview life 2.3s. Contact still gates every reveal. Measured over 66s at 1440×900: gaps 2.0-3.2s typical (one 18s gap seen in the first run and not explained; a second 70s run with call logging was steady at 2.4s), 0 overlap samples, at most 2 preview elements alive.
- **Why earlier rounds looked unchanged.** None of the Visual, About or background work was ever committed; HEAD is still 338f77e. A deployed or cached site shows none of it.
- **Homepage radar previews clashed with rectangles** (2026-10-29). Cause: `.bls` precedes `.obj` in the DOM so rectangles paint over previews, and placement avoided only the rectangles' resting boxes, ignoring the float drift (`--ax/--ay`) and pointer lean. Fix: obstacles use the full drift range plus a margin (`rvBox`), no preview while a rectangle is hovered, a live overlap check just before reveal (`rvClearNow`), and a fade if a leaning rectangle reaches a visible preview. Reproduced before (113×34px under a rectangle). After: 0 overlap samples in 90s soaks at 1440×900 and 1280×720 (about 5 previews each).
- **Black page below the first screen on project pages.** Cause: `#rp0` (the field) is absolute and 880px tall on inner pages, so long case studies (ARCEON is 16,392px) scrolled onto plain black. Fix: project-detail routes use `body.bgfix` and the fixed field (`pj` in `rpInit`). Verified by canvas pixel count at scroll 1400 and screenshots, direct load and in-site navigation.
- ARCEON crop, Hold ring, Chainsaw Man ring: see `DESIGN-SYSTEM.md` (Visual discipline page).
- Chainsaw Man ring on the case-study poster uses the same moon geometry as the card: `csmCard.jpg` is `csm1.jpg` cropped 55px from the top (template match, mean error 6/255), moon centre 50.0% across and 31.3% down `csm1.jpg`, 68.3% of its width. A direct rim fit on `csm1.jpg` was noisy (median error 22px) and was not used.

## Technical constraints
- Shared viewer `lbShow(i, src, sel)`: third argument chooses the image set (defaults to the series pages). It is now a labelled modal dialog: focus moves to Close, Tab is kept inside, Escape returns focus to the opening frame.
- One file, no build, no libraries. Hash routing. `route()` must stop every per-page loop.
- Mouse clicks on `a[href^="#/"]` belong to the global morph handler; custom handlers may `preventDefault` only for touch.
- Lazy images change page height, so in-page jumps re-align after 0.3/0.8/1.5s (`cxJump`).
